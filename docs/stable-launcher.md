# Stable standalone deployment

The standalone server, plugin and skill remain app-owned. The
[CodexMCPBroker](https://github.com/votecoffee/CodexMCPBroker) repository supplies
the pinned shared Python framework and a separate optional Windows management app.
There is no universal plugin requirement. SDK 2.3.0 and framework 0.20.0 remain pinned.

Use a durable application directory outside the checkout, build output and Codex
plugin cache. `scripts/stable_install.py` copies the reviewed Windows Python 3.13
engine, reviewed runtime dependency closure and RECORD-verified application wheel.
Generated bytecode is excluded. A content-addressed inventory retains each file's
SHA-256, config, dependency versions and original wheel hash. Runtime sources and
configuration are retained; ordinary startup does not fetch or install anything.

The installed `Start-Mcp.py` is a stable stdlib entry. The host command is the
explicit retained engine's `python.exe`, arguments `-I -B <app>/Start-Mcp.py`,
and cwd the application directory. It verifies engine, selection, entry and payload
inventories before imports; linked/reparse, missing, malformed and tampered paths
refuse startup. It runs the selected server in the surviving process, without
shell/Node/proxy wrappers. SDK 2.3 retains the original UTF-8 wire handles; no
launch log is written to protocol stdout. Workers use the selected retained runtime.

An atomic `launcher/current.json` selects the snapshot. A nonblocking publisher
lock, expected prior hash, exact byte backup, full proposed verification, fsync,
atomic replace and readback protect publication. Startup takes one complete
selection; an intervening change during verification refuses rather than mixing
generations. Live peers retain imported bytes and their selected worker paths.
An entry implementation change is deliberately refused until separately migrated;
ordinary updates select new backend snapshots through the unchanged entry.
Operational generations retain the same state/admission and registry namespace;
do not bypass existing endpoint/worker limits by silently allocating another state
directory. Separate state is appropriate for disposable acceptance fixtures.

Parent monitoring retains the parent's exact native process handle. Parent death
exits this dedicated process, even if another actor holds a duplicate pipe writer.
Existing supervisor-owned kill-on-close jobs cover all descendants. New owner
jobs have random generation names recorded before child creation. Reconciliation
may retire an eligible resource claim only after exact owner/worker departure,
matching app/ledger generation proof, absent named full-owner job and no barrier
or cleanup receipt. It never terminates an arbitrary process or replays requests.
Legacy and uncertain records stay visible. Attached/shared software is excluded.

Process identities come from retained OS handles and QueryFullProcessImageName,
not `sys.executable`, a launcher alias or a Store/MSIX installation path guess.
The retained engine provides a physical app-owned image path. Unknown or mismatched
native identities fence recovery rather than silently skipping cleanup claims.

Management reports selected installed and running application versions separately.
Plugin versions require actual installation metadata; missing metadata is unknown.
Restart remains unavailable without cross-chat quiescence. Installation, selection,
SDK protocol proof and discovery in an already-open host chat are distinct evidence.

Keep one effective host route and the standalone plugin/skill enabled. Submit the
exact command, arguments, cwd, env, previous route/settings hashes and validation
receipts to the serialized settings publisher. Do not write a stale global TOML
backup over other servers. Use deliberate binary UTF-8 publication and validate
the actual bytes, including LF/CRLF, BOM, Unicode, multiline strings and unrelated
settings. The installer itself never publishes global settings.

New launch acceptance covers cache independence, tamper refusal, peer-preserving
updates, initialize/discovery/current guidance, harmless synthetic reads, EOF,
failed startup, exact owner/parent loss and reconnect. Preserve unchanged native
reader acceptance separately; this launcher does not accept EPLAN editing,
Access/ACE, HTTP, shared GUI hosts or controller operations.
